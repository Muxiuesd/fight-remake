# 开发规范约定

## 一、代码方面

1. 代码架构要清晰明了，可以重复利用的、底层的代码就放入game.muxiuesd.bedrockcore的包中，跟游戏强相关的逻辑代码就在ttk.muxiuesd包下
2. 变量名称、方法名称、类名称要清晰明了
3. 尽可能多给字段、方法和类写注释详细说明
4. 类里面的各种字段最好尽量私有化，适配getter和setter来外部调用，setter方法尽量写条件，防止不小心传入非法的值
5. 一个类里面不要随意写有内部类，除非它们强相关


## 二、架构约定

1. 相同类型的注册元素的Identifier不可重复，持有的id不可重复，也就是同一个注册表不会持有两份相同Identifier的实例。方块与其对应的方块物品会持有相同的Identifier，两者是两个不同的注册表，但id相统一。
2. Identifier在注册阶段就确定，在注册过后不应更改，也不该更改所持有的id字段
3. 能抽象出来重复利用的地方就尽量抽象出来，需要多处地方大量重复利用的逻辑就单独写入对应的工具类
4. 需要被注册的元素大多是整个游戏只有唯一实例的元素（Item、普通的Block），如果它在游戏中不是唯一实例，要么注册的是它的工厂类（如BlockEntityProvider、EntityProvider），要么它自带自己的工厂方法（如BlockWithEntity、Wall）
5. 如果是在某些地方需要一次性大量new的类，最好使用对应的Pool来代替获取，并仔细编写它的回收逻辑
6. 游戏里的system分为游戏系统（GameSystem）与世界系统（WorldSystem），在整个程序生命周期中运行的则是游戏系统，只在游戏游玩阶段的系统是世界系统
