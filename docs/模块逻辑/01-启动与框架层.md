# 01 启动与框架层

> 覆盖：`lwjgl3` 启动器、`game.muxiuesd.bedrockcore.app.GameCore`、`ttk.muxiuesd.FightCore`、屏幕（`Screen`）生命周期、每帧三段式。
> 一句话职责：**把操作系统的一次次“该画一帧了”翻译成“更新全局系统 → 更新当前界面 → 走渲染管线”**，并把所有“只此一份”的注册表在进入主菜单前初始化好。

## 1. 职责与边界

| 做 | 不做 |
|---|---|
| 创建 `Lwjgl3Application`、选择 GL 配置、启动主循环 | 具体画方块/实体（在 §09 渲染管线） |
| 初始化“与存档无关的全局资源”（字体、i18n、事件类型、注册组、着色器、渲染管线、全局系统） | 初始化“与一局游戏有关的注册表”（在 `MainGameScreen.show()`，§04） |
| 管理当前 `Screen` 的切换（主菜单 / 选世界 / 游戏中） | 世界的装卸（在 `ChunkSystem`，§05） |
| 每帧固定三段，并用 `PerfRecorder` 打点 | 决定系统顺序（在 `SystemManager`，§03） |

## 2. 关键类型

| 类型 | 位置 | 作用 |
|---|---|---|
| `Lwjgl3Launcher` | `lwjgl3/src/main/java/ttk/muxiuesd/lwjgl3/Lwjgl3Launcher.java` | `main`，配置窗口/GL，`new Lwjgl3Application(new FightCore(), config)` |
| `GameCore` | `core/src/main/java/game/muxiuesd/bedrockcore/app/GameCore.java` | 框架层 `ApplicationListener` 基类：持有 `activeScreen`、`GameSystemManager`、`RenderPipe`，实现 `create/render/resize/dispose` 骨架 |
| `FightCore` | `core/src/main/java/ttk/muxiuesd/FightCore.java` | 游戏层入口：`coreInit()` 七个注册步骤、三个屏幕、三个全局系统、`initAllSystems()` |
| `MainGameScreen` | `core/src/main/java/ttk/muxiuesd/screen/MainGameScreen.java` | 一局游戏：`show()` 里做 17 步按序初始化 + 建 `MainWorld` + 注册世界渲染处理器 |
| `RenderPipe` / `RenderProcessorManager` | `core/src/main/java/ttk/muxiuesd/render/...` | 按优先级串起所有渲染处理器（详见 §09） |
| `PerfRecorder` | `core/src/main/java/game/muxiuesd/bedrockcore/util/PerfRecorder.java` | 每帧三段计时，`P` 键打印 |

## 3. 启动链（严格按调用顺序）

```
main()                                        [Lwjgl3Launcher]
 └─ new Lwjgl3Application(new FightCore(), config)
     └─ ApplicationListener.create()
         └─ FightCore.create()                 [FightCore.java]
             ├─ coreInit()                     [只做一次、与存档无关]
             │   ├─ Fonts.init()               字体（后续 UI/文本全部依赖）
             │   ├─ FI18N.init()               语言包 zh_cn
             │   ├─ EventTypes.init()          事件类型字符串常量（§11）
             │   ├─ RegistrantGroup.init()     注册表容器本身（不是方块/物品内容，§02）
             │   ├─ ShaderScheduler.init()     着色器编译调度（§09）
             │   ├─ RenderPipe.init()          渲染管线/处理器注册表
             │   └─ GameSystemManager.init()   全局系统：
             │        InputHandleSystem / GUISystem / SpatialAudioSystem
             ├─ 注册 GUI 渲染处理器（RenderProcessorsReg.GUI，优先级 10000）
             │     ← 必须最先注册：它负责画“当前 Screen 的 UI”，永远最后绘制
             ├─ new StartMenuScreen / WorldsMenuScreen / MainGameScreen
             ├─ GameSystemManager.addSystem(...) ×3（见上）
             ├─ GameSystemManager.initAllSystems()   ← 逐个 initialize()
             └─ setScreen(startMenuScreen)           ← 真正开始有 Screen
```

> **为什么要分两次初始化**：`coreInit()` 的东西与“哪一局存档”无关（字体、i18n、着色器）；`MainGameScreen.show()` 的东西与“这一局有哪些方块/物品/配方”有关，退出世界后可以重新初始化。两者的分界线就是 `Screen` 生命周期。

## 4. 每帧三段（`FightCore.render()`）

```
render()
 ├─ exchangeScreen()                 若上一帧请求切屏，在这一帧开头真正切换（保证 update/draw 用同一个 Screen）
 ├─ deltaTime = Gdx.graphics.getDeltaTime()
 ├─ Perf.begin()
 ├─ GameSystemManager.update(delta)  ① 全局系统：输入 → GUI → 空间音频
 ├─ updateScreen(delta)              ② GameCore.updateScreen → activeScreen.render(delta)
 │      └─ MainGameScreen.render: ScreenUtils.clear → world.update(delta)
 └─ RenderPipe.handleGameRender()    ③ 渲染管线：相机更新 → 处理器按优先级绘制 → GUI(10000) 最后
     Perf.end()
```

**顺序为什么不能换**：

- ① 在 ② 之前，所以 `GUISystem.update` 刷新的 `mouseOver` 是本帧新鲜值，`PlayerSystem`/`WorldInputHandleSystem` 才敢用它做门控（§10）。
- ② 只做“世界逻辑推进”，真正绘制全在 ③ 的处理器里；`MainGameScreen.render()` 除清屏外不画任何东西。
- ③ 里 GUI 优先级 10000，保证 UI 永远盖在世界之上。

## 5. 与其他模块的联动

| 方向 | 对象 | 交接内容 |
|---|---|---|
| 下游 | §02 注册 | `coreInit()` 里先建注册表容器；`MainGameScreen.show()` 里再填内容 |
| 下游 | §03 系统 | 全局系统在 `FightCore` 注册，世界系统在 `MainWorld` 注册，二者用同一个 `SystemManager` 实现 |
| 下游 | §04 世界 | `MainGameScreen.show()` 创建 `MainWorld`，`dispose()` 销毁它 |
| 下游 | §09 渲染 | `RenderPipe` 由 `FightCore` 初始化，处理器由 `MainGameScreen` 注册/注销 |
| 下游 | §10 UI | `GUISystem` 是全局系统，`mouseOverUI()` 被世界输入系统读取 |
| 上游 | libGDX | `Gdx.graphics`（delta/尺寸）、`Gdx.input`（键鼠）、`Gdx.gl`（着色器） |

## 6. 刻意设计与代价

- **屏幕切换延迟到帧首**（`exchangeScreen`）：避免在 `render` 中途换屏导致“这一帧用旧屏 update、新屏 draw”。代价：`setScreen` 不是立即生效，调用方不能假设“下一行就切好了”。
- **GUI 处理器优先级 10000 且第一个注册**：靠优先级而非注册顺序决定层级。代价：新增全屏 UI 必须自己算优先级（见 §10）。
- **`dispose()` 顺序**：`GameCore.dispose` 先 `GameSystemManager.dispose()` 再 `getActiveScreen().dispose()`；而 `SpatialAudioSystem` 属于全局系统、`SoundSystem` 属于世界系统 → 音频引擎先死、世界音效后释放（【清单 H12】）。

## 8. 改动指引

- 新增“全局只此一份”的东西 → 放 `coreInit()`，并且**必须**考虑退出世界后是否要重置。
- 新增屏幕 → 在 `FightCore.create()` 里建，用 `setScreen` 切；屏幕自己负责 `show/hide/dispose` 的成对。
- 新增全局系统 → `GameSystemManager.addSystem`，注意它会在**世界系统之前**更新。
