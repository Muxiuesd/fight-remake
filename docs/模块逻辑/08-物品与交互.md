# 08 物品与交互

> 覆盖：`Item`、`ItemStack`、`IItemStackBehaviour` 五个实现、`ConsumptionItem` 全部子类、装备/武器、`use()` 与 `useOn()` 两条入口。
> 一句话职责：**把“手里的东西”变成可执行的两种动作：左键“使用自己”、右键“对世界做点什么”，并且只有真正做成事才消耗**。

## 1. 两条入口（本项目最重要的约定之一）

| 输入 | 触发 | 调用链 | 语义 |
|---|---|---|---|
| **左键** | `PlayerSystem.handleInput`（`PlayerUseItem`） | `LivingEntity.useItem(World)` → `ItemStack.use` → `IItemStackBehaviour.use` → `Item.use(stack, world, user)` | 使用物品**本身**，不认目标 |
| **右键** | `WorldInputHandleSystem` 右键分支 | 先方块实体 `interactWithItem`；`FAILURE` 才 `LivingEntity.useOn(World, Vector2)` → `ItemStack.useOn` → `IItemStackBehaviour.useOn` → `Item.useOn(..., targetPos)` | 对**鼠标指向的坐标**做交互 |

**默认实现**：`Item.use` 与 `Item.useOn` **都返回 false，且都不播音效**。只有真正做成事的子类才覆写、并在成功路径调 `playUseSound(world, user)`。

> 这条默认值是 2026-10-05 改的：此前 `Item.use` 默认播 `ITEM_CLICK` 并 `return true`，导致所有没覆写的材料（骨头/木棍/小麦/史莱姆球…）左键点一下就“成功消耗一个”。

## 2. 行为（behaviour）五件套

| 行为 | 位置 | `use` 做什么 |
|---|---|---|
| `CommonItemStackBehaviour` | `.../stack/behaviour/` | 无耐久则直接 `Item.use`；有耐久走 `HasDurationItemStackBehaviour` |
| `HasDurationItemStackBehaviour` | 同上 | 用一次扣 1 耐久，归零不销毁（`I-E3` 刻意） |
| `ConsumptionItemStackBehaviour` | 同上 | `Item.use/useOn` 返回 true 才 `consume()`（-1，0 则清格） |
| `EquipmentItemStackBehaviour` | 同上 | 找到对应装备槽 → 交换 → 返回 true |
| `WeaponItemStackBehaviour` | 同上 | `useTimer` 冷却 + 挥手 + 扣耐久；返回是否真的挥出 |

`ItemStack.use/useOn` 只是转发到 `behaviour`；**扣不扣数量由 behaviour 决定，而不是由物品自己改数量**。

```

     └─ LivingEntity.useItem                        [LivingEntity.java:276]

```

## 4. 右键交互链（详细）

```
WorldInputHandleSystem.playerInteractWithWorld       [WorldInputHandleSystem.java:156-195]
 ├─ 鼠标格是 BlockWithEntity：
 │    ├─ 空手 → blockEntity.interact(...) → return
 │    └─ 手持 → blockEntity.interactWithItem(...) == SUCCESS
 │              ? （数量 0 则清格）return
 │              : player.useOn(world, mousePos)
 └─ 否则（普通方块/空气/墙）：
      └─ 手持非空 → player.useOn(world, mousePos)
          └─ LivingEntity.useOn                  [LivingEntity.java:289]
              └─ ItemStack.useOn                 [ItemStack.java:81]
                  └─ behaviour.useOn
                      ├─ 默认 false（Common/Equipment/Weapon 都不覆写）
                      └─ ConsumptionItemStackBehaviour.useOn
                          ├─ used = item.useOn(stack, world, user, targetPos)
                          └─ used ? consume : false
```

**当前实现 `useOn` 的物品只有两个**：`CropItem`（种植）与 `BoneMealItem`（催熟）。其它消耗品（`BlockItem`/`WallItem`/`SpawnEggItem`/`EffectItem`）仍是左键 `use`，这是有意保留的现状（未迁移）。

## 5. 消耗品家族（全部继承 `ConsumptionItem`）

| 类 | 触发键 | 成功条件 | 失败时 |
|---|---|---|---|
| `BlockItem` | 左键 | `cs.placeBlock(...)` 返回 true（放置失败已返回 false） | 不扣、不响 |
| `WallItem` | 左键 | 无碰撞冲突且 `cs.placeWall(...)` 为 true | 不扣、不响 |
| `CropItem` | **右键** | `cs.placeAttachment(...)` 为 true | 不扣、不响 |
| `BoneMealItem` | **右键** | 目标是 `Botany` 且 `growLevelIncreaseUpToMax(1)` 为 true | 不扣、不响 |
| `EffectItem` | 左键 | 应用效果后返回 true（自播 `consumeSounds`） | — |
| `SpawnEggItem` | 左键 | `user instanceof Player` 且生成成功 | 不扣、不响 |

## 6. 物品数据模型

- `Item`：注册身份（`identifier`）、`Property`（堆叠上限、使用音效、耐久、减伤、攻击力…）、`Renderer`。
- `ItemStack`：`item + amount`（+ 耐久的 property 副本）。构造**直接赋** `amount`（`ItemStack.java:66` 的 `Math.max(amount, 1)`），绕过 `setAmount` 的夹取；`setAmount`（`:328-336`）才会 `min(maxCount)` 并忽略负数。
- 装备：`EquipmentItemStackBehaviour` 把装备放进 4 个装备槽；`EquipmentItem.use` 覆写只是为了让“换上装备”算成功（否则默认 false 会被判失败）。
- 武器：`Sword` 自己播音效并返回是否命中；`RangedWeapon` 发射子弹（子弹类型有兜底问题，`H23`）。

## 8. 刻意设计与代价

- **默认静默失败**：失败必须无声无息，否则玩家以为用出去了；消耗品据此决定扣不扣。代价：忘记覆写 `use`/`useOn` 的物品会“完全没反应”，只能靠文档/陷阱表提醒。
- **扣数量下沉到 behaviour**：物品不自己 `setAmount`，避免“物品说成功、堆叠没减”。代价：想给某个物品定制消耗（如一次用 2 个）必须新写 behaviour。
- **方块实体优先**：右键命中方块实体时，物品交互只在 `FAILURE` 后执行。代价：`interactWithItem` 返回 `SUCCESS` 的物品会被“吞掉”，需要方块实体自己负责把物品放对槽位。

## 10. 改动指引

- 新增“左键使用自己”的物品：覆写 `use()`，成功路径 `playUseSound` + `return true`。
- 新增“右键作用于世界”的物品：覆写 `useOn(..., targetPos)`，**不要**覆写 `use()`（默认 false 正好让左键无效）。
- 新增消耗规则：写新 behaviour，而不是在物品里直接改 `amount`。
