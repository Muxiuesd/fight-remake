# 04 世界与生命周期

> 覆盖：`World`、`MainWorld`、`WorldInfoTypes`、进入/退出世界、世界信息的读写。
> 一句话职责：**持有“这一局”的系统表与世界级共享数据，并在进入时读盘、退出时落盘**；它自己不实现任何玩法。

## 1. 职责与边界

| 做 | 不做 |
|---|---|
| 持有 `WorldSystemsManager`，把 `update` 转发给全部系统 | 系统内部逻辑（§05~§13） |
| 管理 `WorldInfoTypes`（世界名、种子、游戏时间等共享标量） | 存档文件的具体格式（§12） |
| 进入世界时 `readWorldInfo()`，退出时 `writeWorldInfo()` | 区块的装卸（§05） |
| 决定世界系统的注册顺序（`MainWorld.addAllSystems`） | 渲染（§09） |

## 2. 关键类型

| 类型 | 位置 | 说明 |
|---|---|---|
| `World` | `core/src/main/java/ttk/muxiuesd/world/World.java` | 150 行；抽象基类，持有 `WorldSystemsManager` |
| `MainWorld` | `.../world/MainWorld.java` | 44 行；`addAllSystems()` 注册 20 个系统（顺序即契约） |
| `WorldInfoTypes` | `.../registry/WorldInfoTypes.java` | `INT`/`LONG`/`FLOAT`/`STRING` 四个静态 map：世界里任何“全局标量”都放这 |
| `WorldInfo` | `.../world/WorldInfo.java` | 只有 `name`/`seed` 等种子信息，`Codec` 化后写 `world.json` |

## 3. 进入世界的链

```
WorldsMenuScreen（选/建世界）                      [screen/WorldsMenuScreen.java]
 └─ new MainGameScreen(worldName)
     └─ show()                                    [MainGameScreen.java:39-57]
         ├─ 17 步注册：Pools → EquipmentTypes → EventTypes → Sounds → BlockEntities
         │    → Blocks → Walls → EntityTypes → Entities → StatusEffects → Items
         │    → WorldInfoTypes → ItemGroups → CraftingRecipes → BlockDropLootTables
         │    → EntityDeathLootTables → AttachmentPlacements
         ├─ World.setWorldName(worldName)
         ├─ new MainWorld(this)                    ← 构造里 readWorldInfo()
         ├─ registerWorldRenderProcessors()        ← 4 个世界处理器（§09）
         ├─ world.addAllSystems()                  ← 20 个系统
         ├─ world.setWorld(this) / initAllSystems()
         └─ guiRenderProcessor.setMainGameScreen(this)   ← 让 GUI 处理器知道画谁
```

> 17 步的顺序不是随意的：`Blocks` 要在 `Walls`/`Items` 之前（物品引用方块），`Items` 要在 `ItemGroups`/配方/掉落表之前（它们引用物品），`AttachmentPlacements` 最后（规则要引用已注册的方块与附着物）。

## 4. 每帧与退出

```
MainGameScreen.render(delta)                 [MainGameScreen.java]
 ├─ ScreenUtils.clear(Color.BLACK)
 └─ world.update(delta)                      [World.java:46]
     └─ getSystemManager().update(delta)     ← 20 个系统按注册顺序跑

MainGameScreen.dispose()
 ├─ unregisterWorldRenderProcessors()        ← 先摘渲染任务，否则处理器还引用已 dispose 的世界
 ├─ world.dispose()                          [World.java:53]
 │   ├─ getSystemManager().dispose()         ← 系统按注册顺序 dispose
 │   ├─ WorldInfoTypes.STRING.putIfNull(Fight.WORLD_NAME)
 │   └─ writeWorldInfo()                     ← 写 world.json（失败只 Log.error）
 └─ guiRenderProcessor.setMainGameScreen(null)
```

**顺序理由**：渲染处理器持有世界引用（相机、区块数据），必须先于 `world.dispose()` 摘掉；`guiRenderProcessor` 复位是为了主菜单不被上一局的夜景着色器染色（`P-C14`）。

## 5. 世界信息（`WorldInfoTypes`）逻辑

- `readWorldInfo()`（`World.java:84`）：**先清空** `INT/LONG/FLOAT/STRING` 四张表（防止从 A 世界进 B 世界时串数据），再 `RawObjectJsonConverter.fromJson` + `WorldInfo.CODEC.decode`；`result.result().isPresent()` 才用，否则 `new WorldInfo()`（首次进世界/无文件）。
- `writeWorldInfo()`（`:114`）：try/catch 包住写盘，失败只 `Log.error`——**静默**，属 `S2`/`P-B12` 家族。
- `TimeSystem` 的 `GAME_TIME` 就放在 `WorldInfoTypes.FLOAT`：构造时 `putIfNull` 读出，`dispose` 写回。
- `setWorldName`（`:67`）条件写反（`worldName == null || !worldName.isBlank()` 时报错），但**全项目零调用**（`H7`）。

## 6. 与其他模块的联动

| 方向 | 对象 | 交接内容 |
|---|---|---|
| 上游 | §01 启动 | `FightCore` 建三个 Screen；`MainGameScreen.show()` 完成世界初始化 |
| 上游 | §02 注册 | 17 步初始化依赖 `RegistrantGroup`、`Blocks`、`Items` |
| 下游 | §03 系统 | `addAllSystems()` 注册 20 个系统，`TimeSystem` 排第一 |
| 下游 | §05 区块 | `ChunkSystem` 读写世界共享的 `WorldInfoTypes`（种子、时间） |
| 下游 | §12 存档 | `readWorldInfo/writeWorldInfo` 是“世界级”存档入口；区块/实体是“分片级” |
| 下游 | §09 渲染 | 屏幕负责注册/注销世界渲染处理器 |

## 7. 刻意设计与代价

- **世界系统顺序固定**：不引入依赖注入，靠 `addAllSystems` 的书写顺序表达依赖。代价：调序会在 `initialize` 里 NPE（`ChunkSystem` 依赖 `PlayerSystem`、`EntitySystem` 依赖 `TimeSystem`）。
- **`WorldInfoTypes` 用静态 map**：任何系统都能读写，无需传参。代价：跨世界会串，必须靠 `readWorldInfo` 开头清空来兜；新增字段忘了清就会串档。
- **退出时才写 `world.json`**：减少写盘频率。代价：崩溃丢世界信息。

## 9. 改动指引

- 新增世界级标量：放进 `WorldInfoTypes` 对应类型表，**并把它加进 `readWorldInfo` 的清空清单**。
- 新增世界系统：在 `MainWorld.addAllSystems()` 里按依赖顺序插入，同时更新本文 §3 的顺序表。
- 新增 Screen：`show()` 里做初始化、`dispose()` 里按“渲染处理器 → 世界 → GUI 引用”的逆序清理。
