# 11 事件·音频·粒子·光照

> 覆盖：`EventBus`/`EventHandler`/`EventTypes`、`SoundSystem`/`SpatialAudioSystem`/`AudioHolder`、`ParticleSystem`、`LightSystem`。
> 一句话职责：**把“世界里发生了什么”广播出去（事件），并让声音、粒子、光照这些“表现层”各自订阅，互不直接依赖**。

## 1. 事件（解耦的主通道）

```
EventTypes.XXX = "event.xxx"                    [EventTypes.java]
EventBus.eventHandlersTable : ConcurrentHashMap<String, EventHandler>
 ├─ register(type, handler)
 │    ├─ 已存在 → Log.error 后**覆盖**（不抛）
 │    └─ put
 ├─ post(type, payload)
 │    ├─ 未注册 → Log.error + throw IllegalArgumentException
 │    └─ handler.callEvents(payload)
 ├─ subscribe / unsubscribe
 │    ├─ 未注册 → Log.error + throw（subscribe/post）
 │    └─ unsubscribe 未注册 → 只 Log.error（不抛）
EventHandler<T>
 ├─ HashSet<T> events（具体事件的子类型集合）
 ├─ addEvent/removeEvent：先 contains 再增删，返回 boolean
 └─ getEvents() 直接暴露内部 Set（可被外部改）
```

**已注册的事件**（部分）：`BLOCK_REPLACE`、`BLOCK_DESTROY`、`WORLD_TICK`、`BULLET_SHOOT`、`LIVING_ENTITY_DEATH`、`PLAYER_*`… 事件是“过去时”，订阅者不应回写状态；回写一律通过系统调用。

## 2. 音频

| 类型 | 位置 | 作用 |
|---|---|---|
| `SoundSystem` | `.../system/SoundSystem.java` | 世界系统；`playSpatialSound(AudioHolder, SpatialAudioSource)`（`:206`，另有重载 `Entity`/`BlockEntity`），方块三音效 `playWalkSound(:113)`/`playPutSound(:139)`/`playDestroySound(:147)` |
| `SpatialAudioSystem` | `.../system/game/SpatialAudioSystem.java` | 全局系统；持有 `SpatialAudioEngine`（TuningFork 封装） |
| `AudioHolder` | `.../audio/AudioHolder.java` | 一条音频（sound/music 的 id + 音量 + pitch） |
| `AudioLoader`/`AudioPlayer` | `.../audio/` | 加载与播放；音乐/音效分开 |

```
方块被破坏 → EventBus.post(BLOCK_DESTROY/REPLACE)
 └─ EventBlockDestroy/Replace.handle
     └─ SoundSystem.playSpatialSound(blockSounds.walk(), source)
         └─ SpatialAudioSystem.playAudio(...) → audioEngine.createAudio(...)
```

**订阅式的好处**：`ChunkSystem` 只负责“方块变了”，不需要知道声音怎么播；加新音效只改订阅者。

**注意**：`BlockSounds.DEFAULT` 有静态初始化顺序问题（`H14`），`getSounds().walk()` 会 NPE。

## 3. 粒子

- `ParticleSystem`（世界系统）持有发射器与粒子池；方块破坏时由 `ChunkSystem` 直接调 `blockBreakParticle`（同步生成，不经事件）。
- 粒子在 `PARTICLE` 处理器（优先级 400）里绘制，位于实体之上、UI 之下。
- 对象池化：粒子/`ParticleEffect` 从池取还，避免每帧 new。

## 4. 光照与昼夜

- `LightSystem` 是**世界系统**，需要真实 GL（着色器编译）；它向 `DAYNIGHT_SHADER` 提供昼夜 uniform。
- 昼夜来自 `TimeSystem.isDay/isDusk/isNight`；`GAME_TIME` 存在 `WorldInfoTypes.FLOAT`。
- 时间变化 → 光照 uniform 渐变 → 三个世界处理器（地下/区块/地面）都受影响。

## 5. 与其他模块的联动

| 方向 | 对象 | 交接内容 |
|---|---|---|
| 上游 | §03 系统 | `SoundSystem`/`LightSystem` 是世界系统；`SpatialAudioSystem` 是全局系统 |
| 上游 | §05/§06 方块 | 放置/破坏 → `BLOCK_REPLACE`/`BLOCK_DESTROY` 事件 |
| 上游 | §07 实体 | 攻击/受击/死亡 → 事件 + 音效 |
| 下游 | §09 渲染 | 粒子/光照结果由渲染管线绘制 |
| 平行 | §13 生成 | 刷怪不发声，但死亡走掉落/事件 |

## 6. 刻意设计与代价

- **事件只广播、不回写**：避免“谁最后改谁赢”的隐式顺序问题。代价：需要回写时必须显式调用系统。
- **音频引擎在全局系统、世界音效在世界系统**：生命周期不同（引擎跨世界复用）。代价：`dispose` 顺序错了就 use-after-free（`H12`）。
- **粒子同步生成、不走事件**：方块破坏要“立刻看到碎屑”，事件队列会晚一帧。代价：`ChunkSystem` 直接依赖粒子系统。

## 8. 改动指引

- 新增事件：`EventTypes` 加常量 → `EventBus.register` 在初始化阶段完成 → 订阅者实现 `EventHandler`。
- 新增音效：`Sounds` 注册 `AudioHolder` → 方块/物品 `Property` 里引用 → 由订阅者播放。
- 新增粒子：在 `ParticleSystem` 注册发射器，别在 `ChunkSystem` 里直接 new。
