# 12 存档与序列化

> 覆盖：`Codec`/`CodecBuilder`/`ObjectCodec`/`FieldBinding`/`ParamField`、`RawObject`/`RawObjectJsonConverter`、`CodecChunk`、实体/玩家编解码、原子写盘、存档目录结构。
> 一句话职责：**把“对象图”压成“只有 id + 字段”的 JSON，并且保证写盘要么成功要么不破坏原文件；读档失败时必须能降级但不能悄悄覆盖。**

## 1. 数据格式

```
save/<世界名>/
 ├─ world.json                     ← WorldInfo（名字、种子）
 └─ world/
     ├─ chunks/<x>_<y>.json        ← 一个区块一个文件
     ├─ entities/<x>_<y>.json      ← 一个区块的实体列表
     └─ player.json                ← 玩家（位置/背包/装备/血量）
```

每个文件都是 `RawObject` 的 JSON：`{"type": "...", "fields": {...}}`，字段可嵌套 `RawObject`/数组。

## 2. 关键类型

| 类型 | 位置 | 说明 |
|---|---|---|
| `Codec<T>` | `core/src/main/java/game/muxiuesd/bedrockcore/serialization/Codec.java` | `encode(T)` / `decode(RawObject)`，返回 `DataResult<T>` |
| `ObjectCodec`/`CodecBuilder` | 同上 | 声明式字段绑定：`field(...)`/`paramField(...)`/`factory(...)` |
| `FieldBinding`/`ParamField` | 同上 | 字段名 ↔ getter/setter，或构造参数 |
| `RawObject` | 同上 | 中间表示（可嵌套、可数组） |
| `RawObjectJsonConverter` | 同上 | `RawObject` ↔ JSON 字符串 |
| `DataResult` | 同上 | `success(value)` / `failure(message)` |
| `CodecChunk` | `core/src/main/java/ttk/muxiuesd/serialization/codecs/CodecChunk.java` | 区块编解码（方块/墙体/附着物/高度/群系） |
| `UnifiedFileUtil` | `.../util/UnifiedFileUtil.java` | `writeFileAtomic`（临时文件 + 原子替换） |

## 3. 读档链（区块）

```
ChunkLoadTask.call()                                [ChunkLoadTask.java]
 ├─ 文件存在 → RawObjectJsonConverter.fromJson → Chunk.CODEC.decode(raw)
 │    └─ CodecChunk.decode
 │        ├─ new Chunk()                            ← 无 chunkSystem（防止解码期登记）
 │        ├─ setBiome / setCanSpawn / 高度
 │        ├─ 遍历方块：Registries.BLOCK.getOrNull(id) → chunk.setBlock(block, x, y)
 │        │    └─ chunkSystem == null，所以不会触发 addBlock   ← Chunk.setBlock 的判空就是为这里
 │        └─ 遍历附着物：Attachment.CODEC.decode → chunk.setAttachment(attachment, x, y)
 ├─ 有逐格错误 → DataResult.error(..., chunk) 仍带出部分区块 → System.out 一行   ← N1/S2
 ├─ 解析抛异常（JSON 截断/语法错）→ catch：先取“正在卸载的同位置区块”，否则 genNewChunk()   ← N1/S2
 └─ 返回 Chunk
```

**关键不变量**：解码期 `Chunk` 不带 `chunkSystem`，所以不会在**加载线程**里登记系统；登记统一在 `ChunkSystem.addChunk`（主线程）完成。这是 `D1` 的边界，也是 `S1` 在生成路径上被破坏的原因。

## 4. 写档链

```
ChunkUnloadTask.call()                              [ChunkUnloadTask.java]
 ├─ Chunk.CODEC.encode(chunk) → RawObject
 ├─ RawObjectJsonConverter.toJson
 └─ UnifiedFileUtil.writeFileAtomic(path, json)      ← 临时文件 + 原子替换
```

- 写档失败的处理：`RawObjectJsonConverter` 里 `printStackTrace` 后继续（`RawObjectJsonConverter.java:120-122`），属“静默失败”。
- 实体/玩家同理，各自 `Codec`。

## 5. 基本类型 Codec（有坑）

| 类型 | 行为 | 问题 |
|---|---|---|
| `INT`/`LONG`/`FLOAT` | 直接转换 | — |
| `BOOL` | `isInt` 分支 `value == 0 → success(true)` | **语义反了**（`Codec.java:100-105`，注释说“非法值一律 false”） |
| `STRING` | `null → "Null_String"` | 把 null 变成合法字符串，掩盖错误 |
| `Identifier` | `命名空间:路径` | 非法格式由 `Identifier` 构造校验 |

| 方向 | 对象 | 交接内容 |

| 上游 | §02 注册 | 解码只认 id；未知 id 要 `getOrNull` + 报错或跳过 |
| 上游 | §04 世界 | `World.readWorldInfo/writeWorldInfo` 是世界级入口 |

## 7. 刻意设计与代价

- **只有 id、不存对象**：存档体积小、可兼容；代价是“注册表里删了一个 id，旧存档就解不出来”，必须显式处理（`getOrNull` + `IllegalArgumentException("…（旧存档数据）")`）。
- **原子写**：不会写出半个文件。代价：临时文件与磁盘占用；且“写失败”目前只打印。
- **解码期 `Chunk` 不带 `chunkSystem`**：把“数据解码”和“系统登记”分开。代价：任何绕过 `addChunk` 的路径都会漏登记（历史 `P-B10`）。

## 9. 改动指引

- 新增可存档状态：优先 `ICatData`（`readCatData/writeCatData`），别改 `CodecChunk` 的顶层结构。
- 新增 Codec：用 `CodecBuilder` 声明字段，`factory` 里返回 `createInstance()`（多实例）或原型（单例）。
- 改存档格式：**必须**同时写“旧档如何降级/报错”，并更新 `docs/问题清单.md` 的存档章节。
