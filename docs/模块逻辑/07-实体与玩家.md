# 07 实体与玩家

> 覆盖：`Entity`、`LivingEntity`、`Player`、`EntitySystem`、`PathFindingEntity`、状态效果、击退、碰撞与伤害入口。
> 一句话职责：**定义“会动的东西”的生命周期与移动模型；玩家只是多了一个输入源和被门控的交互能力**。

## 1. 继承层次

```
Entity<T>（x/y、hitbox、property、sounder、update）
 ├─ LivingEntity<T>（生命、背包、装备、状态机、状态效果、击退、攻击/受击）
 │   ├─ Player（防御、isUsingItem、鼠标朝向、丢物、36 格背包）
 │   └─ 生物：Chicken / Zombie / PufferFish …
 └─ ItemEntity（掉落物，生命周期 + 拾取）
     └─ Bullet（子弹，飞行 + 命中）
```

`EntityType` + `EntityProvider` 决定“能不能造”：单例注册原型、`createSelf()` 造实例；存档只存 typeId + 位置/状态。

## 2. 每帧链（`EntitySystem`）

```
EntitySystem.update(delta)                          [EntitySystem.java]
 ├─ 延迟增删：_addEntities / _removeEntities 并入正式表
 ├─ 遍历 alive 实体 → entity.update(delta)
 │    ├─ Entity.update：更新 hitbox 中心
 │    └─ LivingEntity.update：                    [LivingEntity.java:150-173]
 │         ① super.update（hitbox 中心）
 │         ② updateStatusEffect(delta)（状态效果本身）
 │         ③ 背包 tick（Backpack 内部倒计时）
 │         ④ 三个计时器：attackedTimer / effectPreSecondTimer / effectPreTickTimer
 │         ⑤ 击退物理：衰减并强制写回速度（放在状态机之前，击退结束本帧立即恢复）
 │         ⑥ 状态机（EntityState）：idle/move/attack…（`!isKnockback()` 才跑）
 │         ⑦ 挥手动画计时
 ├─ 玩家移动意图由 PlayerSystem 写入（WASD → 速度 lerp）
 └─ 碰撞：GroundEntityCollisionSystem / BulletCollisionSystem（独立系统，按序在 EntitySystem 之后）

EntitySystem.tick()  ← 20Hz，AI/寻路决策（PathFindingEntity 用 FlowField）
```

**移动模型**（`EntitySystem.java:336-356`，`D10`）：

- **意图（帧级）**：本帧有没有输入、朝哪、多快——立即生效。
- **惯性（秒级）**：无意图时按“1 - 0.5^(delta/halfLife)”衰减，与帧率无关。
- **击退**：直接写速度并跳过摩擦/意图，衰减完再交还控制。

## 3. 玩家（`Player`）

| 能力 | 实现 | 备注 |
|---|---|---|
| 移动 | `PlayerSystem.handleInput` 读 WASD，逐轴 lerp 到目标速度 | 松开即归零（防滑行），斜向归一化 |
| 朝向 | 鼠标世界坐标 → 方向 | 渲染/攻击都用它 |
| 防御 | `defendCDTimer`（2s 冷却）+ `defendDurationTimer`（0.3s 持续） | **两个计时器没成对启停**，见 `B20` |
| 使用物品 | `isUsingItem = useItem(world)` → 左键 | `WorldInputHandleSystem` 用它挡“同一帧挖方块” |
| 交互 | `useOn(world, 鼠标世界坐标)` → 右键 | 与左键互不影响 |
| 丢物 | `dropItem`：方向 = 鼠标方向，速度 = min(距离, 4) | 先 `setVelocity` 再 `setCurSpeed`（顺序反了会被 MIN_SPEED 清零） |
| 背包 | 36 格 + 4 装备槽 + `handIndex` | UI 槽位直接读写它（§10） |

**输入门控**（`PlayerSystem.java:201`）：只有 `当前屏幕 == PLAYER_HUD_SCREEN` 且 `!GUISystem.mouseOverUI()` 时，鼠标操作才生效；键盘只受“是否在游戏内”限制。

## 4. 状态效果与伤害

```
DamageType.apply(...)                                [DamageType.java:39-48]
 ├─ 基础伤害
 ├─ 装备减伤：equipmentItemStack.getProperty().get(PropertyTypes.DAMAGE_REDUCTION)
 │    ← Float 拆箱；缺键会 NPE（N-B? / B?，旧存档/非装备物品）
 └─ 状态效果修正（部分效果跳过护甲，F-C17 待确认）

StatusEffect：挂在 LivingEntity 上，双 TaskTimer（持续时间 + 触发间隔）
```

## 5. 生命周期与存档

- 实体加入：`EntitySystem.add(entity)` → 进 `alive` + 对应渲染系统（地面/地下）。
- 实体移除：`remove(entity)`，延迟执行；掉落物由 `ItemEntityGetter` 生成。
- 区块卸载：`EntitySystem.unloadEntities(chunkPos)` 把该区块实体写盘并摘除；加载时 `loadEntities(chunkPos)` 反向。
- 存档：`EntityCodecBuilder` 写 `typeId + 位置 + 各字段`；`ItemEntity` 构造**丢弃了传入的 `EntityType`**、硬编码 `EntityTypes.ITEM_ENTITY`（`B26`，子类化掉落物会解错类型）。

## 7. 刻意设计与代价

- **意图模型**（`D10`）：用“本帧意图 + 秒级衰减”替代加速度积分，手感可控且帧率无关。代价：无意图时仍有惯性，碰撞后需要额外处理。
- **玩家不持有输入**：输入在 `PlayerSystem`，`Player` 只存状态。代价：`Player` 无法自测“按下会怎样”，测试要跨层。
- **实体延迟增删**：遍历安全、可在一个 tick 里批量生成。代价：`add`/`remove` 互不查对方队列，同帧先 add 后 remove 无法抵消（`N12`）。

## 9. 改动指引

- 新增生物：`Entities.register` + `EntityTypes` + 生成工厂 + 掉落表；AI 放 `tick`，表现放 `update`。
- 新增玩家能力：状态放 `Player`，输入放 `PlayerSystem`，**门控条件必须与 `mouseOverUI` 一致**。
- 改移动手感：只动 `EntitySystem` 的“意图/惯性”两段，不要在子类里直接改 `x/y`。
