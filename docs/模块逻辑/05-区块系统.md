# 05 区块系统

> 覆盖：`ChunkSystem`、`Chunk`、`ChunkLoadTask`/`ChunkUnloadTask`、`MainWorldChunkGenerator`、区块坐标换算。
> 一句话职责：**把“无限世界”切成 16×16 的区块，按玩家位置异步装卸、原子落盘，并且是所有方块级操作的唯一入口**。

## 1. 职责与边界

| 做 | 不做 |
|---|---|
| 按玩家位置计算“该加载/该卸载”的区块，提交线程池、收割 `Future` | 生成具体地形（在 `MainWorldChunkGenerator`） |
| 维护 `activeChunks`（可见）、`_loadChunks`/`_unloadChunks`（在途缓冲） | 方块的行为（§06） |
| **所有**方块的放置/破坏/替换/墙体/附着物 | 实体的管理（§07） |
| 区块级坐标换算、`getBlock/getWall/getAttachment/getChunk` 查询 | 渲染（§09，`ChunkRenderSystem` 只读） |

## 2. 关键类型与数据结构

| 类型 | 位置 | 说明 |

## 3. 每帧逻辑链（`ChunkSystem.update`）

```
update(delta)                                        [ChunkSystem.java:150-227]
 ├─ ① 收割加载任务 Future
 │    ├─ 成功 → addChunk(chunk)                        [:167]
 │    └─ EntitySystem.loadEntities(chunkPos)           ← 实体比区块晚一帧到位
 ├─ ② 收割卸载任务 Future → removeChunk(chunk)
 ├─ ③ _loadChunks 全部并入 activeChunks                [:189-192]
 ├─ ④ 提交“需要卸载”的区块到卸载池，然后 activeChunks.removeAll + 清空缓冲  [:194-207]
 │      注释：“提交后立即清空，防止下一帧重复提交同样的卸载任务”
 ├─ ⑤ 每个 activeChunk: chunk.update() + blockEntity.update()  [:209-217]
 └─ ⑥ 若 chunkLoadTimer 到点且玩家移动过：重算“该加载/该卸载”集合  [:219-223]
```

**为什么 ③ 与 ④ 是分开的**：加载是“解码完成 → 下一帧才可见”，避免主线程同步生成（`D2`）；卸载是“先摘出活跃表 → 再异步写盘”，避免同一区块被提交两次卸载任务、并发写同一文件（`D9`）。

## 4. 区块坐标与查询

| 操作 | 实现 | 注意 |
|---|---|---|
| 世界坐标 → 区块坐标 | `Chunk.worldToChunk(wx, wy)`（`Chunk.java:39`）用 `% 16` 处理负数 | 与 `getChunkPosition` 的 `fastFloor(/16)` 是两套写法 |
| 世界坐标 → 格坐标 | `Util.fastRound(wx, wy)`（四舍五入） | **格坐标 = 方块左下角**，`Block.WIDTH=HEIGHT=1f` |
| 区格坐标查方块 | `Chunk.getBlock(cx, cy)`（`:137`）要求 `0..15` | 传世界坐标请用 `seekBlock`（`:222`） |
| 查区块 | `ChunkSystem.getChunk(wx, wy)`（`:937`）**只扫 `activeChunks`** | 在途区块返回 null（`D2`，刻意） |
| 查方块 | `getBlock(wx, wy)`（`:880`）区块缺失时返回 `Blocks.ARI` | 不返回 null |
| 查附着物 | `getAttachment(wx, wy)`（`:922`） | 与放置使用同一套取整 |

## 5. 方块级入口（全部收敛在这里）

```
placeBlock(newBlock, wx, wy)                        [ChunkSystem.java:441]
 ├─ newBlock == null → 抛 NPE（契约：调用方不许传 null）
 ├─ chunk == null → return false（区块没加载，静默失败）
 ├─ 旧 BlockWithEntity → removeBlockEntity + removeBlockInstance
 ├─ if (oldBlock != null && oldBlock != Blocks.ARI)
 │    ├─ destroyAttachment(round.x, round.y)        ← 同格！附着物失去支撑（D6）
 │    ├─ playDestroySound / blockBreakParticle / dropDestroyed
 ├─ chunk.setBlock(blockWithEntity.createSelf() 或 newBlock)
 │    └─ Chunk.setBlock 内部转发 ChunkSystem.addBlock（D1）
 └─ EventBus.post(EventTypes.BLOCK_REPLACE, ...)    ← 声音/寻路/统计靠这个
```

| 方法 | 行 | 语义 |
|---|---|---|
| `destroyBlock(wx, wy)` | `:493` | 等价 `placeBlock(Blocks.ARI, ...)`，**不碰墙体** |
| `placeWall(wall, wx, wy)` | `:505` | 空气/水不可放；`wall.createSelf(round)` 建实例（原型碰撞箱在世界原点）；先判实体重叠；再走与 `placeBlock` 同款收尾；通知寻路 |
| `destroyWall(wx, wy)` | `:549` | 无墙静默返回；清格 + 寻路通知 + 音/粒子/掉落 |
| `placeAttachment(attachment, wx, wy)` | `:598` | `getChunk` 判空 → `fastRound` → 该格已有附着物返回 false → `AttachmentPlacements.canPlaceOn(getBlock(wx,wy), attachment)`（**同格**）→ `createInstance()` + `addBlock` + `chunk.setAttachment` |
| `destroyAttachment(wx, wy)` | `:631` | 取实例 → `beDestroyed()`（掉包）→ `removeBlockInstance` → `chunk.setAttachment(null)` |
| `dropDestroyed(block, wx, wy)` | `:574` | 战利品表优先，`getOrNull` 查物品，`ItemEntityGetter` 生成掉落物并设拾取延迟 |

## 6. 挂载/卸载时对“实例”的登记（历史的坑）

```
addChunk(chunk)                                     [:247-261]
 ├─ chunk.setChunkSystem(this)
 ├─ 遍历 blocks → addBlock(block, worldX, worldY)
 │    └─ Attachment + isInstanceAttachment → addBlockInstance（进 blockInstances + TimeSystem）
 └─ 遍历 attachments → isInstanceAttachment → addBlockInstance   ← 读档出来的植物靠这一步复活

removeChunk(chunk)                                  [:266-285]
 ├─ BlockWithEntity → removeBlockEntity(block, false)   ← false：不 drop，内容还在区块数组里
 └─ Attachment + isInstanceAttachment → removeBlockInstance
```

**为什么卸载不 drop**：区块内容会随 `ChunkUnloadTask` 原样写盘，重载时再挂回来；`beDestroyed()` 会掉包，等于复制物品（与 `removeBlockEntity(..., false)` 同一套理由）。这也是历史缺陷 `P-B10` 的修复点：漏了加载侧的登记，会导致“读档后植物不生长 + 挖掉下方方块崩溃”。

## 8. 刻意设计与代价

- **D1 写入即登记**：`Chunk.setBlock` 无条件转发 `addBlock`，保证“区块数组”与“系统登记”永不脱节。代价：生成线程也走这条路 → `S1`（线程越界）。
- **D2 在途区块不可见**：`getChunk` 对加载中的区块返回 null。代价：≤1 帧空窗，只影响排在 `ChunkSystem` 前的系统。
- **D8 五处查重**：`chunkExist` 依次查 active/加载任务/`_loadChunks`/卸载任务/`_unloadChunks`，防“量子幽灵线程”造出重复实例。代价：`chunkExist` 复杂度高，新增挂载路径必须接入。
- **D9 卸载先摘表再写盘**：代价是卸载途中该区块读出来是空气。

## 10. 改动指引

- 任何“往世界里放/删东西”的功能，都必须走 `placeBlock/placeWall/placeAttachment`，不要直接 `chunk.setBlock`（会绕过登记与事件）。
- 新增“每格独享”的方块类型：确认 `createInstance() != this`，并在 `addChunk`/`removeChunk` 的实例登记分支里覆盖到。
- 改坐标换算：先读 `ChunkSystem` 里 `D7` 的两处封板注释，再决定要不要动。
