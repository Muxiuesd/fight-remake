# 06 方块·墙体·附着物

> 覆盖：`Block`/`BlockAir`/`BlockWater`/`BlockWithEntity`、`Wall`、`Attachment`/`Botany`、`BlockEntity`、`AttachmentPlacements`、方块掉落表。
> 一句话职责：**定义“世界里能占据一个格子的三种图层”（方块 / 墙体 / 附着物）以及它们的行为、存档与放置规则**。

## 1. 三层图层模型

一个格子里最多同时有三样东西，互相独立：

| 图层 | 基类 | 每格实例？ | 例子 |
|---|---|---|---|
| 方块 | `Block` | 多数共享单例（`BlockWithEntity` 每格实例） | 草、石头、耕地、水 |
| 墙体 | `Wall<?>` | **每格新实例**（`createSelf(round)`） | 木墙 |
| 附着物 | `Attachment extends Block` | 共享型（`createInstance()==this`）或每格型（`Botany`） | 土豆、小麦、木棍 |

`Chunk` 里就是三个平行的 `[16][16]` 数组：`blocks`、`walls`、`attachments`。

## 2. 类型与职责

| 类型 | 位置 | 关键点 |
|---|---|---|
| `Block` | `core/src/main/java/ttk/muxiuesd/world/block/abs/Block.java` | `WIDTH=HEIGHT=1f`；`identifier`、`property`、`hitbox`；`bePlaced`/`beDestroyed`/`update` |
| `BlockAir` | `.../block/instance/BlockAir.java` | 空气，`Blocks.ARI`；所有“没有方块”的查询都返回它而非 null |
| `BlockWater` | `.../block/instance/BlockWater.java` | `walkable=false`、`swimmable=true`，摩擦 0.77 |
| `BlockWithEntity` | `.../block/abs/BlockWithEntity.java` | 每个格子持有 `BlockEntity`；`createSelf()` 造每格实例 |
| `Wall<?>` | `.../world/wall/Wall.java` | 独立障碍，碰撞箱填满整格；`createSelf(pos)` 造实例 |
| `Attachment` | `.../block/abs/Attachment.java` | `CODEC`、`fromId`、`createInstance()`、`beDestroyed()` 掉包 |
| `Botany` | `.../block/abs/Botany.java` | `growLevel`、`maxGrowLevel()`、`isFullyGrown()`、`growLevelIncreaseUpToMax()`、`Tickable`、`ICatData` |
| `BlockEntity` | `.../block/abs/BlockEntity.java` | 槽位、`interact`/`interactWithItem`、`update`/`tick`、`Codec` |
| `AttachmentPlacements` | `.../registry/AttachmentPlacements.java` | 白名单/黑名单两种放置规则，每个附着物只能注册一种 |

## 3. 放置链（玩家侧）

### 3.1 方块（左键 `BlockItem.use`）

```
BlockItem.use                                        [BlockItem.java:36]
 └─ cs.placeBlock(this.block, mouseWorld.x, mouseWorld.y)
     └─ 失败 return false（物品不消耗、不播音效）
```

### 3.2 墙体（左键 `WallItem.use`）

`WallItem.use` → `cs.placeWall(wall, x, y)`：空气/水拒绝、实体占位拒绝、同格已有墙则先拆旧。

### 3.3 附着物（右键 `CropItem.useOn`）

```
WorldInputHandleSystem 右键（非方块实体分支）        [WorldInputHandleSystem.java:186/192]
 └─ player.useOn(world, mouseWorldPosition)
     └─ LivingEntity.useOn → ItemStack.useOn → CropItem.useOn   [CropItem.java:35]
         └─ cs.placeAttachment(attachment, targetPos.x, targetPos.y)   [ChunkSystem.java:598]
             ├─ 该格已有附着物 → false
             ├─ AttachmentPlacements.canPlaceOn(getBlock(wx, wy), attachment)   ← 同格！
             └─ createInstance() → addBlock → chunk.setAttachment
```

**放置规约**（`AttachmentPlacements`）：

```
canPlaceOn(ground, attachment)                       [AttachmentPlacements.java]
 ├─ ground == null || attachment == null → false
 ├─ ground instanceof BlockAir → false（空气上永不可放）
 ├─ 没有该附着物的规则记录 → false（没登记 = 永不可放）
 └─ 白名单：ground 在列表里才 true；黑名单：ground 不在列表里就 true
```

规则登记在类的 `static {}` 块里（如 `registerWhitelist(Blocks.POTATO, Blocks.FARMLAND_DRY)`），`init()` 只负责打印；`Blocks.READY` 用于防止“规则比方块先加载”导致唯一一条规则被静默丢弃。

## 4. 破坏链

| 触发 | 链 | 结果 |
|---|---|---|
| 左键空手/非功能物品 | `WorldInputHandleSystem:128-155` → 附着物 → 墙体 → 方块（else-if，只打一层） | 每层各自 `destroyXxx`，掉落/音效/粒子都下沉到 `ChunkSystem` |
| 方块被替换（放置/挖掉） | `placeBlock` 内 `destroyAttachment(round.x, round.y)` | 同格附着物失去支撑，一并破坏（`D6`） |
| 附着物自身被破坏 | `destroyAttachment` → `beDestroyed()` | 按 `getDroppedItem()` 掉包，带随机偏移与拾取延迟 |
| 墙体被破坏 | `destroyWall` | 清格 + 通知寻路 + 音/粒子/掉落 |

**方块掉落**：`BlockDropLootTables` 优先；没有表则 `Registries.ITEM.getOrNull(block.getID())`；再 `ItemEntityGetter.get(...)` 生成 `ItemEntity`，`setLivingTime(Fight.ITEM_ENTITY_PICKUP_SPAN)`。

## 5. 植物生长（`Botany`）

```
Botany.tick()                                        [子类 BotanyPotato / BotanyWheat]
 ├─ TimeSystem.isDay() && random() > 0.999
 └─ isFullyGrown() ? return : growLevelIncrease(1)

Botany.maxGrowLevel()  ← 抽象：土豆 3（4 张图）、小麦 7（8 张图）
Botany.isFullyGrown()  = growLevel >= maxGrowLevel()
Botany.growLevelIncreaseUpToMax(v)  ← 骨粉用，夹到上限，返回是否真的长了
```

渲染侧 `AttachmentRenderer` 用 `Math.min(level, textureRegions.length - 1)` 取图，所以上限写大不会崩，只会一直画最后一张。

存档：`Botany.readCatData/writeCatData` 用键 `"growLevel"`（`CatInt`），随 `CodecChunk` 的 `"attachments"` 写盘。

## 6. 方块实体（`BlockEntity`）

```
BlockWithEntity（工作台/熔炉）
 ├─ createBlockEntity(pos, world)  ← 首次放置/加载时创建
 ├─ 槽位：BlockEntity.getSlot(GridPoint2) → 找不到返回 null（调用方必须判，见 N19）
 ├─ interact(world, player, grid)             空手交互（取出等）
 ├─ interactWithItem(world, player, stack, grid)  手持物品放入（返回 SUCCESS/FAILURE）
 └─ tick()（TimeSystem 20Hz）  熔炉烧炼、工作台刷新输出
```

**方块实体优先于物品交互**：右键命中 `BlockWithEntity` 时，先 `interactWithItem`，返回 `SUCCESS` 就直接 return（物品已被方块实体收下），只有 `FAILURE` 才继续 `player.useOn(...)`（§08）。

## 8. 刻意设计与代价

- **附着物与支撑同格**（`D6`）：`placeAttachment` 用 `getBlock(wx, wy)` 校验，而不是 `wy-1`。代价：`ChunkSystem` 里字段名仍叫 `below`，且 `placeBlock` 的注释（`ChunkSystem.java:460-462`）前半句写“同格”、括号里却又写“附着物继续附着在下方方块上”——后半句是纠正前的心智模型残留（空气格不可能有附着物，`canPlaceOn` 对空气返 false），读代码时以代码为准。
- **附着物必须登记规则**：没登记 = 永不可放（结构性防冲突）。代价：新增作物时忘了登记，表现为“右键没反应”，且不报错（只有 `Log.error`）。
- **每个附着物只能注册一种规则**（白名单或黑名单）：防止同一附着物两套规则互相覆盖。代价：想表达“除了 A 都不能种”只能用黑名单，需要枚举全部例外。
- **共享型附着物直接放原型**（生成器）：生成期与读档写的是同一份区块数据，不登记实例。代价：共享型附着物没有每格状态，要状态就必须用 `Botany`。

## 10. 改动指引

- 新增作物：建 `Botany` 子类（实现 `maxGrowLevel()`）→ `Blocks.registerBotany(..., 阶段贴图)` → `Items.register(name, Blocks.XXX)` → **在 `AttachmentPlacements` 静态块登记规则** → 掉落表/物品组按需。
- 新增方块实体：继承 `BlockWithEntity` + `BlockEntity`，实现 `Codec`，并在 `MainGameScreen.show()` 的 `BlockEntities.init()` 里注册。
- 新增墙体：`Walls.register(...)`，注意 `createSelf` 必须返回**新实例**（原型碰撞箱在世界原点）。
