# 15 战利品表

> 本文覆盖 `world/loottable/` 全部内容与三个注册类。行号以当前工作树为准。
> 编号引用：`P-C1`、`N-B11` 见 [../问题清单.md](../问题清单.md)；`D*`/`N*`/`B*` 见 [../项目逻辑链条与模块评审.md](../项目逻辑链条与模块评审.md)。

## 1 职责与边界

**做**：
- 描述“什么东西会掉什么”：一组互斥条目（`LootGroup`）+ 每个条目的权重与数量区间（`LootEntry`）。
- 提供统一的抽取算法（`LootGenerator`）：逐组独立、按权重加权、可控制重复。
- 把表登记进注册表（`Registries.BLOCK_DROP_LOOT_TABLE` / `ENTITY_DEATH_LOOT_TABLE` / `FISHING_LOOT_TABLE`），让触发方**按 id 查表**而不是引用具体表对象。
- 生成掉落时负责“把 `ItemStack` 变成世界里的 `ItemEntity`”（位置、初速、拾取方式、寿命）。

**不做**：
- 不判断“该不该掉”（夜晚/幸运值/工具品质等）——由触发方决定，或由 `LootCondition` 这一层很薄的开关表达。
- 不持有实体、不参与 tick、不进存档：战利品表是**只读的静态数据**，存档里存的只有物品 id 与数量。
- 不负责物品注册：表里写的是 `Items.FISH` 这类已注册的 `Item`，注册顺序见 §3.1。

## 3 逻辑链条

### 3.1 注册期

`core/src/main/java/ttk/muxiuesd/screen/MainGameScreen.java:55-58`：

```java
BlockDropLootTables.init();
EntityDeathLootTables.init();
FishingLootTables.init();
AttachmentPlacements.init();
```

三个 `init()` 都**只打一行日志**——真正的登记发生在各注册类的**类初始化**里：

- `BlockDropLootTables.java:25-45` 的 `static { ... }` 里一批 `dropSelf(...)`；
- `EntityDeathLootTables.java:25/33/42/50` 用**字段初始化式**：`public static final EntityDeathLootTable CHICKEN = register(Entities.CHICKEN, ...)`；
- `FishingLootTables.java:24` 同样是字段初始化式：`public static final FishingLootTable FISHING = register("fishing", ...)`。

顺序要求：必须排在 `Items.init()`(:51) 之后，因为表里引用 `Items.FISH`/`Items.RUBBISH` 等具体物品。

> 两种写法都能工作：`BlockDropLootTables` 用 `static {}`（表多、用 `dropSelf` 一行一张），实体与钓鱼表用字段初始化式（一眼能看到表名）。新表建议照字段初始化式写，静态块只留给“批量生成的同类表”。

### 3.3 附着物（植物）被破坏

分开走，因为植物有成熟度：

所以同一张表里用 `LootCondition.MATURE` / `IMMATURE` 分组，就能做到“成熟掉果实、未成熟掉种子”。

### 3.6 抽取算法

`LootGenerator.generate`（`LootGenerator.java:51`）：

1. 按顺序遍历 `groups`，**每组各自独立抽取** `rollCount` 次；
2. 每次在组内把 `weight` 累加，取一个 `[0, total)` 的随机数落在哪一段；
3. `allowDuplicates == false` 时把已抽中的条目从**工作副本**里 `iterator.remove()`（源表的 `List` 不动）；
4. `luck` 参与权重：`calculateEffectiveWeight`(:86) = `weight * (1 + luck / 100f)`，所以 `luck = 100` 等于权重翻倍（对组内所有条目同倍放缩，不改变相对比例）；
5. 每个条目 `entry.get()` 产出 `ItemStack`；数量随机到 0 时返回 `ItemStack.VOID`，生成处 `isVoid()` 跳过。

## 5 刻意设计与代价

1. **分组在构建时定型，运行时不重新分组**（`LootGroup` 的注释与 `AI开发协作规范` 四.0）。代价：想“运行时按条件换组”只能改表结构，不能临时分组；换来的是生成路径零分配、无 `groupingBy` 开销（旧钓鱼实现就是运行时 `groupingBy`，已删）。
2. **表里存 `ItemStack` 模板，`get()` 返回副本**：`copy(amount)` 而不是 `copy()`——因为 `ItemStack.copy(int)` 会把 0 抬成 1（`ItemStack` 里 `Math.max(amount,1)`），所以 0 必须提前变成 `ItemStack.VOID`（`LootEntry.java:92`）。
3. **按 id 查表，不缓存表对象**：`BlockDropLootTables.generate` 每次 `getOrNull`。代价：多一次 `HashMap` 查找；换来的是“没登记 = 不掉”这条规则天然生效，且 mod 可以在启动后任意替换表。
4. **三类表各自带自己的 `Conditions`**：方块多 `mature`、钓鱼多 `hookPos`/`pullTarget`/`pullSpeed`/`luck`、实体只有 `pos`。代价：每个新场景都要写一个 `Conditions` 子类 + 一个注册类的一步式入口；换来的是表本身完全不知道“自己是怎么被触发的”。
5. **方块与墙体一律 `mature=false`**，只有附着物走 `beDestroyed` 传真实成熟度。这是“方块没有成熟度概念”的直接后果，不是遗漏。
6. **`luck` 目前不在玩法里**：钓鱼恒传 100、其它两处恒传 0。参数通路已经打通（`LootGenerator` 的 `calcEffectiveWeight`），但没有物品/状态去改它。

## 7 改动指引

**加一种方块的掉落**
1. 在 `registry/BlockDropLootTables.java` 的 `static {}` 里加一行：`public static final BlockDropLootTable X = register(Blocks.X.getIdentifier(), BlockDropLootTable.Builder.create().dropSelf(Blocks.X).build());`
2. 需要多个物品/概率时改用 `.setGroups(LootGroup.of("x", LootEntry.of(Items.A, 1, 1, 70f), LootEntry.of(Items.B, 1, 2, 30f)))`。
3. 不加这一行 = 打掉什么都不掉（`getOrNull` 返 null），这是**预期**，不是 bug。

**加一种生物的死亡掉落**
1. 在 `registry/EntityDeathLootTables.java` 里 `register(Entities.X, EntityDeathLootTable.Builder.create().setGroups(...).build());`
2. 想“有概率什么都不掉”就加一条 `LootEntry.of(ItemStack.VOID, 1, 1, w)`。

**改钓鱼战利品**
1. 只改表内容：`registry/FishingLootTables.java:24` 的 `LootGroup.of("fishing", ...)`。
2. 要加“按鱼竿等级分表”这类逻辑：先加一张表并注册（`register("fishing_2", ...)`），再给 `FishingLootTables.generate` 加表 id 参数——**不要**在 `FishingLootTable` 里判断鱼竿。

**新增一类表（例如“开箱掉落”“钓鱼宝藏”）**
1. 新类 `implements LootTable<XxxLootTable.Conditions>`，`Conditions extends LootTable.Conditions<Conditions>` 并加场景字段；
2. `Builder` 照 `EntityDeathLootTable.Builder`（`create/setGroups/setRollCount/setAllowDuplicates/build`）；
3. `RegistryKeys` 加 `RegistryKey`、`Registries` 加 `create(key)`；
4. 新建 `registry/XxxLootTables`：表用**字段初始化式**注册，`init()` 只打日志，提供一个一步式 `generate(...)`（内部 `getOrNull`，null 直接 return）；
5. 在 `MainGameScreen.show()` 的 `Items.init()` 之后加一行 `XxxLootTables.init();`。
