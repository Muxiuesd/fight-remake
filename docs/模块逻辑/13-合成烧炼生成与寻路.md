# 13 合成·烧炼·生成·寻路

> 覆盖：`CraftingRecipes`/`CraftingRecipeRegistry`/`ShapedCraftingTableRecipe`、`BlockEntityCraftingTable`、`CookingRecipe`/`BlockEntityFurnace`、`MonsterGenerationSystem`/`UndergroundCreatureGenSystem`、`PathfindingSystem`/`FlowField`/`PathFindingEntity`。
> 一句话职责：**四个“被驱动”的子系统——合成/烧炼响应 UI 交互，生成响应时间与玩家位置，寻路响应墙体变化并给实体指方向**。它们都不拥有自己的主循环，全部挂在世界 `update` 或 `tick` 上。

## 1. 合成

```
CraftingRecipes.init()                    ← MainGameScreen.show() 第 13 步
 └─ 逐个 register(ShapedCraftingTableRecipe)
     └─ CraftingRecipeRegistry.register     ← 线性列表

交互：
WorldInputHandleSystem 右键 → blockEntity.interactWithItem(hand)
 ├─ 输出槽 → FAILURE（不许往输出槽放）
 └─ 输入槽 → 放入/合并

BlockEntityCraftingTable.tick(20Hz)       [BlockEntityCraftingTable.java:125]
 └─ updateOutput()
     └─ CraftingRecipeRegistry.findRecipe(inventory)   ← 线性扫描
         └─ ShapedCraftingTableRecipe.matches(grid)
             ├─ 3×3 建表 → 裁掉空边 → 编码字符串
             ├─ 原版 + 水平镜像各比一次
             └─ 命中后写入输出槽（new ItemStack + 属性 copy）

空手右键取输出：interact                     [BlockEntityCraftingTable.java:49-83]
 ├─ 容器空 → FAILURE
 ├─ getSlot(interactGridPos) → 可能为 null
 └─ 取 1 个 → 遍历所有非空槽各扣 1
```

**配方匹配的语义**：只比“形状 + id”，**忽略数量**；3×3 网格自动裁边，所以 2×2 配方可以放在任意角。

## 2. 烧炼

```
BlockEntityFurnace.interactWithItem        [BlockEntityFurnace.java]
 ├─ 输入槽 → 放入（同一物品才合并）
 ├─ 燃料槽 → 放入（消耗品当燃料）
 └─ 输出槽 → FAILURE

BlockEntityFurnace.tick(20Hz)
 ├─ 有输入 + 有燃料 + 输出可容纳
 ├─ cookTimer 累加，满 60 tick 出一炉
 └─ CookingRecipe.match(stack)
     └─ input.equals(stack)   ← 含 Property 全等
```

**经验教训**：`equals` 比到 Property，意味着“同名但耐久不同的工具”不算同一种输入；反过来，取出时若 `new ItemStack(item, 1)` 重建会**丢掉 Property**（`N-B15`，破损工具放进去再取出＝耐久洗白）。

## 4. 寻路

```
PathfindingSystem.onWallChanged()          [PathfindingSystem.java:121-128]
 └─ dirty = true; wallVersion++

PathfindingSystem.update(delta)             [:69-95]
 ├─ 目标移动 ≥ 1 格 或 dirty → rebuildFlowField()   [:103-116]
 │    └─ dirty 重建后不重置 rebuildTimer → N26 可能连跑两帧
 └─ 否则 0.4s TaskTimer 定时重建

FlowField.build()                           [FlowField.java:72]
 ├─ origin = floor(target) - 32           ← SIZE=64，通常不是 16 的倍数
 ├─ 缓存 4×4 区块（baseChunkX = floor(origin.x/16)）
 ├─ 基础可走性 isWalkableBase              ← floor(wx/16) - floor(origin.x/16)
 ├─ 墙体膨胀 isWallCell                    ← 用 lx/16 选区块（N25 错位）
 └─ 反向 BFS 写 cost[]/dirIndex[]

消费：Entity.update → PathFindingEntity
 └─ getFlowDirection(entityPos) → FlowField.getDirection → O(1) 查表
```

**为什么用流场**：目标每格一个方向向量，所有追同一目标的实体共享一张表，比每个实体 A* 便宜一个数量级。

## 6. 刻意设计与代价

- **配方线性扫描**：配方少（当前十几个），线性足够；代价是 O(配方数) × 每 tick 一次（20 次/秒）。
- **烧炼用 `equals` 含 Property**：避免“铁镐和木镐混烧”。代价是取出的重建必须保留 Property。
- **生成靠三道闸 + 计时器**：防止在白天/超限时刷怪。代价是闸门提前 return 时计时器不走（`N22`）。
- **流场 0.4s 重建**：墙体不常变，省 CPU。代价是“刚放墙”到“实体绕路”最多 0.4s 延迟。
- **墙变化整表重建**：不做增量。代价是大地图重建卡顿风险（当前 4×4 区块可控）。

## 8. 改动指引

- 新增配方：`CraftingRecipes.register`，形状用字符串矩阵，注意“忽略数量”的语义。
- 新增熔炉配方：`FurnaceRecipes`，输入物品必须与 `equals` 语义一致。
- 新增刷怪：实现 `GenFactory`，在系统里注册；别在系统里写死实体类型。
- 改寻路：先改 `FlowField` 的坐标换算，**务必**让 `isWalkableBase` 与 `isWallCell` 用同一套 `floor` 语义。
