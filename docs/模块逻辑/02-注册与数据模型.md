# 02 注册与数据模型

> 覆盖：`Registries`、`Identifier`、`Blocks`/`Items`/`EntityTypes`/`WallRendererRegistry` 等注册入口、`Property`/`PropertyTypes`、`ICatData`（存档附加数据）、`ItemGroups`。
> 一句话职责：**给“世界里的一切种类”一个稳定的字符串身份，并保证“存档里只出现身份，不出现对象”**。

## 1. 职责与边界

| 做 | 不做 |
|---|---|
| `Identifier` 校验、不可变、值语义 | 决定对象在世界上怎么表现（在 §06/§07/§08） |
| 维护 `id → 对象` 的双索引（`id` 字符串 + `Identifier`） | 保存每格/每个实体的实例状态（在 §12，用 `Codec`/`ICatData`） |
| 让单例类型“注册实例”、多实例类型“注册工厂” | 管物品怎么用（§08） |
| 注册期做参数校验（缺 id、重复注册、空工厂） | — |

## 2. 关键类型

| 类型 | 位置 | 说明 |
|---|---|---|
| `Identifier` | `core/src/main/java/ttk/muxiuesd/id/Identifier.java` | `命名空间:路径`，构造时 `Pattern.matches` 校验；`equals/hashCode` 基于字符串；**不可变** |
| `Registries` | `core/src/main/java/ttk/muxiuesd/registrant/Registries.java` | 静态字段：`BLOCK`/`ITEM`/`ENTITY_TYPE`/`PROPERTY_TYPE`/`BIOME`/`WALL`/`STATUS_EFFECT`… |
| `Registry<T>` | `.../interfaces/Registry.java`（实现 `Registries.DefaultRegistry`） | 内部两张表：`LinkedHashMap<String, Identifier> idMap` + `LinkedHashMap<Identifier, T> regedit`；`register` 重复直接抛 `RuntimeException("注册Id：… 重复！！！")`，取用有 `get`（未注册抛）与 `getOrNull`（返 null）两支 |
| `Blocks` | `core/src/main/java/ttk/muxiuesd/registry/Blocks.java` | 314 行，所有方块/墙体/附着物的**字段** + `init()`；`register(...)` 同时注册渲染器 |
| `Items` | `.../registry/Items.java` | 物品注册，重载多（`register(String)` / `(String, Supplier)` / `(String, Attachment)` / `(Block)` / `(Wall)`） |
| `Property` / `PropertyTypes` | `.../property/`、`.../registry/PropertyTypes.java` | 物品/方块的“键值属性袋”，如 `ITEM_MAX_COUNT`、`ITEM_USE_SOUND`、`DAMAGE_REDUCTION` |
| `ICatData` | `.../interfaces/ICatData.java` | “可写进存档的附加数据”：`readCatData(DataHolder)` / `writeCatData(DataHolder)` |

## 3. 注册链（以方块为例）

```
Blocks.init()                                  [Blocks.java:29-31 现在只打印一行]
 ├─ 字段初始化（类加载时按声明顺序执行）
 │   ARI = registerCommon("air", ...)          → register("air", "air", ...)
 │   GRASS = registerCommon("grass", ...)
 │   ...
 │   POTATO = registerBotany("potato", BotanyPotato::new, "potatoes_stage_0..3.png")
 │   WHEAT  = registerBotany("wheat",  BotanyWheat::new,  "wheat_stage_0..7.png")
 │   STICK_ATTACHMENT = registerAttachment("stick", ...)   ← 用 StandardRenderer，见 §06
 │   CRAFTING_TABLE / FURNACE = registerBlockEntity(...)
 └─ 末尾：static final boolean READY = true;   ← 用来防“规则登记早于方块注册”

register(Identifier id, Supplier<T> factory, BlockRenderer<T> renderer)   [Blocks.java:281-295]
 ├─ T block = factory.get()                  ← 原型对象，只此一份（单例类型）
 ├─ block.setIdentifier(id)
 ├─ Registries.BLOCK.register(id, block)     ← 存档只认这个 id
 ├─ Registries.BLOCK_RENDERER.register(id, renderer)
 └─ if (block instanceof BlockWithEntity) Registries.BLOCK_ENTITY_RENDERER.register(id, ...)
```

**多实例类型的关键差别**：`Attachment`/`Botany` 虽然是单例注册，但 `createInstance()` 会造新对象（`Attachment` 返 `this`，`Botany` 返新对象并复制 id/droppedItem）。注册表里的是**原型**，世界里的是**实例**，二者用 `getBlockKey` 区分（§05）。

## 4. 取用契约（决定要不要判空）

| 方法 | 未命中行为 | 调用方该不该判空 |
|---|---|---|
| `Registries.BLOCK.get(Identifier)` | **抛** `RuntimeException("注册Id：… 不存在！！！")` | **不判**，抛了就是 bug |
| `Registries.BLOCK.getOrNull(String)` | 返回 `null`，注释写明“用于存档解码等容错路径” | **必须判**，且判完要决定“降级还是报错” |
| `SystemManager.getSystem(String)` | 抛 | 不判 |
| `SystemManager.getSystem(Class)` | `Log.error` 后返 null（“可选系统”语义，`D12`） | 必须判，但这是设计而非缺陷 |
| `Registries.BLOCK.getOrNull` 在 `Codec` 里 | 见 §12 | 同上 |

> 这是项目里最容易踩的一条：**同一个“找不到”，有的入口抛、有的返 null**（`S3`）。新增入口时先决定语义，并把语义写进方法名（`…OrNull`）。

## 5. 数据归属三层

| 层 | 存什么 | 例子 | 谁负责 |
|---|---|---|---|
| 注册表原型 | 种类级、全世界共享 | `Blocks.POTATO` 的贴图名数组、物品最大堆叠 | 本模块 |
| 每格/每实体实例 | 位置相关状态 | `Botany.growLevel`、`BlockEntity` 的槽位、实体血量 | §05/§06/§07 |
| 存档 | 只有 id + 附加数据 | `CodecChunk` 写 `"botany": {"id": "...", "property": {...}}` | §12 |

**判据**：能被所有实例共用的，放原型；随位置/时间变化的，放实例；实例状态要跨存档的，实现 `ICatData` 或进 `Codec`。

## 6. 与其他模块的联动

| 方向 | 对象 | 交接内容 |
|---|---|---|
| 上游 | §01 启动 | `FightCore.coreInit()` 里 `RegistrantGroup.init()` 只建**旧的**注册器容器（`@Deprecated`，现仅 mod api 与 `BlocksReg`/`ItemsReg` 用）；游戏内容实际由 `MainGameScreen.show()` 的 17 步直接填 `Registries.*` |
| 下游 | §05 区块 | 解码方块/附着物时 `Registries.BLOCK.getOrNull(id)`；缺 id 抛 `IllegalArgumentException`（`Attachment.fromId`、`EntityCodecBuilder` 是正确范式） |
| 下游 | §06 方块 | `Blocks.register` 顺带注册渲染器；`BlockWithEntity` 再注册实体渲染器 |
| 下游 | §08 物品 | `Items.register(name, Attachment)` 会 `crop.setDroppedItem(cropItem)`，把“作物方块”和“种子物品”互相绑定 |
| 下游 | §12 存档 | `Identifier` 是存档里唯一的种类标识；`Property` 序列化成 `RawObject` |
| 平行 | §13 配方 | `CraftingRecipes`/`FurnaceRecipes` 全部引用 `Items.*`，必须在 `Items.init()` 之后 |

## 7. 刻意设计与代价

- **单例注册实例、多实例注册工厂**：省内存、存档只存 id；代价是“原型”和“实例”必须分清，`Attachment.createInstance() == this` 被 `isInstanceAttachment` 用来判定是否每格独享（§05）。
- **`Identifier` 不可变 + 正则校验**：可以对它做 map key、可以直接进存档；代价是运行时拼 id 要新建对象（`Fight.ID()` 用 `synchronized` 复用 `StringBuilder` 抵消一部分）。
- **`Blocks.READY` 放在所有字段之后**：静态字段按声明顺序初始化，`AttachmentPlacements` 的静态块若早于 `Blocks` 完成就会拿到 null 并**静默丢掉规则**；`READY` 是给这种顺序错误报错的哨兵（§06）。

## 9. 改动指引

- 加方块/物品：先加字段 + `registerXxx`，再考虑渲染器、掉落表、物品组、配方；**附着物还要登记放置规则**（§06）。
- 加注册表：在 `RegistrantGroup.init()` 里加一行，并在 `Registry` 上明确 `get`/`getOrNull` 的语义。
- 加可存档状态：优先 `ICatData`（挂在方块/实体上），不要往 `Codec` 里塞特例。
