# 09 渲染管线

> 覆盖：`RenderPipe`、`RenderProcessorManager`、`RenderProcessor`、相机（`CameraController`/`PlayerCamera`）、`ChunkRenderSystem`、实体/粒子渲染、`LightSystem` 与昼夜着色器。
> 一句话职责：**每帧把所有“要画的东西”按优先级排成一条流水线，先更相机，再逐个处理器“取任务 → begin → 画 → end”，UI 永远最后**。

## 1. 职责与边界

| 做 | 不做 |
|---|---|
| 相机更新（跟随玩家、视口） | 世界逻辑（§05/§07） |
| 按优先级串行执行处理器（100 地下实体 / 200 区块 / 300 地面实体 / 400 粒子 / 10000 GUI） | 决定“哪些东西存在”（系统层） |
| 每个处理器独立 `begin/end`（批次隔离） | 合批优化（当前逐格绘制） |
| 着色器调度（`ShaderScheduler`）、光照 uniform | 纹理加载（`FightAssetManager`，§14） |

## 2. 关键类型

| 类型 | 位置 | 说明 |
|---|---|---|
| `RenderPipe` | `core/src/main/java/ttk/muxiuesd/render/RenderPipe.java` | `init()` 建管理器；`handleGameRender()` 是每帧入口 |
| `RenderProcessorManager` | `.../render/RenderProcessorManager.java` | 持有全部处理器，`swap()` 快照后按 `getRenderOrder()` 升序执行 |
| `RenderProcessor` | `.../render/abs/RenderProcessor.java` | 抽象：`recognize(RenderTask)`、`addRenderTask`、`render()`；内部按 z 排序 |
| `CameraController` / `PlayerCamera` | `.../render/camera/` | 视口尺寸、跟随玩家；`PlayerCamera.INSTANCE` 单例 |
| `ChunkRenderSystem` | `.../system/ChunkRenderSystem.java` | 收集可见区块并逐格绘制方块/墙体/附着物 |
| `WorldChunkRenderProcessor` | `.../render/instance/` | 只负责 `recognize` 区块渲染任务 |
| `GroundEntityRenderSystem` / `UndergroundEntityRenderSystem` | `.../system/render/` | 实体绘制（先画阴影再画实体） |
| `LightSystem` | `.../system/LightSystem.java` | 光照/昼夜，需要真实 GL |

## 3. 每帧链

```
FightCore.render()
 └─ RenderPipe.handleGameRender()                    [RenderPipe.java:63]
     ├─ 相机 update（跟随玩家 + 视口）
     ├─ ProcessorManager.swap()                       ← 取本帧任务快照，避免遍历中改集合
     └─ handleRender()
         ├─ (100) ENTITY_UNDERGROUND  渲染地下实体
         ├─ (200) WORLD_CHUNK         渲染区块（方块→墙体→附着物三层）
         ├─ (300) ENTITY_GROUND       渲染地面实体（阴影先于实体）
         ├─ (400) PARTICLE            渲染粒子
         └─ (10000) GUI               渲染当前 Screen 的 UI（永远最后）
             每个处理器：begin() → 逐个 render task → end()
```

**没有 `process(delta)`**：渲染只读“本帧已由逻辑层准备好的数据”；顺序完全由优先级决定，不靠注册顺序。

## 4. 区块渲染（当前实现）

```
ChunkRenderSystem.draw()
 ├─ collectVisibleChunks(camera)        ← 视锥剔除（:105 与 :212 各调一次，重复）
 └─ 对每个可见区块、每个格子：
      ├─ 取 Block → BlockRenderer.render（纹理 + 位置）
      ├─ 取 Wall → WallRenderer.render
      └─ 取 Attachment → AttachmentRenderer.render
           └─ Botany 按 growLevel 取帧，Math.min(level, 贴图数-1) 夹取
```

**当前是逐格绘制、不拆批次**：贴图不同就 flush，`Context` 从池里取还。代价是 draw call 多；正确性优先于性能。

`AttachmentRenderer` 只加 `OFFSET_X`（不加 `OFFSET_Y`）——附着物锚在**格子左下角**；方块渲染器用 `OFFSET_X/OFFSET_Y` 居中。`STICK_ATTACHMENT` 因为要“居中 + 向上”，改用 `BlockRenderer.StandardRenderer`（见 `Blocks.java:149-153` 注释）。

## 5. 相机与坐标

- `CameraController` 用 `viewportWidth/Height` 计算视口；**历史 bug**：`viewportHeight * (w/h)` 是整数除法，1280×720 比例算错、高>宽时视口为 0（黑屏）。
- 世界坐标 = 格坐标（左下角）× 1.0；相机看到的是“以玩家为中心”的矩形。
- 鼠标 → 世界坐标：`Util.getMouseWorldPosition()`（屏幕→相机反投影），放置与交互都靠它。

## 6. 光照与着色器

- 三个世界处理器（地下/区块/地面）用 `ShadersReg.DAYNIGHT_SHADER`，`LightSystem` 提供昼夜 uniform。
- `ShaderScheduler` 负责编译/热替换；`GL32CMacIssueHandler` 处理 macOS 兼容。
- 退出世界时必须复位 GUI 处理器的 `mainGameScreen` 引用，否则主菜单会被上一局夜景染色（`P-C14`）。

| 方向 | 对象 | 交接内容 |

## 8. 刻意设计与代价

- **优先级即层级**：100/200/300/400/10000，UI 永远最后。代价：新增“要盖在世界之上但又在 UI 之下”的层（如准星）必须自己选一个中间值。
- **每处理器独立 begin/end**：互不污染批次状态。代价：draw call 变多；且两个 `begin()` 写在 `try` 之外（`RenderProcessorManager.java:129-130`），若 `begin` 自己抛异常，`finally` 不会执行、当帧渲染直接中断（正常路径下 `batch.end()`/`shapeRenderer.end()` 都有 try/catch 兜底，所以不是“永久坏死”）。
- **逐格绘制**：实现简单、正确性高。代价：没有合批（`N13`/性能债）。

## 10. 改动指引

- 新增“要画的东西”：在对应系统的 `draw` 里产出 render task，交给已有处理器；不要新建管线。
- 新增渲染层：选优先级 + 注册到 `RenderProcessorManager`，并在 `MainGameScreen` 注册/注销。
- 改相机：同时检查 `resize`、`CameraUtil`、UI 坐标换算（UI 用的是另一套正交相机）。
